# 私有声音库（可选扩展）

公开的 noai 只提供通用判断与通用曲子。真正决定“像不像这位作者”的，是作者自己改过、认可过、拒绝过的句子。这些句子属于作者的私有资产，不进入本仓库。本文件只定义 noai 怎样读取和写入调用方提供的私有声音库；没有私有库时，noai 行为与以前完全一致。

## 怎样找到私有库

按顺序取第一个存在的目录：

1. 调用方在交接中明确给出的声音库路径（例如写作或准备环节的 `voiceDir` 字段）。
2. 环境变量 `NOAI_VOICE_DIR`。
3. 都没有：只用公开曲子，不猜路径、不新建目录，并在完整报告中写“未加载私有声音库”。

## 目录约定

```
<voice-dir>/
├── VOICE.md          # 声音卡：作者怎样说话、明确不要什么，常驻读取，控制在约 2k 以内
├── pairs/            # 正式对照：作者确认过的“改前 → 改后 → 为什么”
│   └── <主题>.md
└── candidates/       # 候选对照：自动回流写入，尚未升级为正式对照
    └── <日期>-<来源>.md
```

每条对照至少包含：改前、改后、为什么（指出对理解、意图、语气或记忆的具体影响）、适用载体（文章／图文／详情页／视频／短文／通用）、来源（任务与版本）。拒绝型对照写成“检测信号 → 为什么误伤 → 保留原文”。

## 读取时怎样用

- **步骤 1.5 建语感卡时**：先读 `VOICE.md`，它是有依据的目标声音，优先级高于从当前初稿推断出的暂定特征，低于本次任务的 `approvedLanguage`、锁定句和用户本次明确要求。
- **步骤 2 生成前**：按当前载体读取 `pairs/` 中适用的对照，与公开曲子一起建立先验；同一问题上作者对照与公开曲子冲突时，以作者对照为准。
- **候选只作参考**：`candidates/` 可以提示风险，不能单独作为“必须改”的依据，也不能覆盖锁定句。
- 载体不同的对照不互相套用：详情页的短促卖点句不能拿来改文章正文，反之亦然。只有标注“通用”的对照跨载体使用。

## 反馈写回哪里

存在私有库时，步骤 6 的反馈写入 `<voice-dir>/candidates/`。作者明确授权公开的（本仓库作者 2026-11-18 已授权：他的去 AI 味对照两边都留一份），同时追加到本仓库 `references/anti-examples.md`，让公开版也越用越好；未授权的不写入本仓库。

- 每条记录一次真实修改：作者改了什么、接受或拒绝了哪条建议、给出的原因。
- 同一判断原则在不同任务里出现 3 次及以上，或作者明确说“以后都这样”，才由维护者升级进 `pairs/` 或 `VOICE.md`；升级不是 noai 的自动动作。
- 只有作者逐条确认、并已去掉私人正文和可识别信息的通用对照，才可以另行提交到公开 `samples/`。

不存在私有库时，沿用步骤 6 原有规则：只有用户授权才在本技能目录沉淀脱敏反馈。
