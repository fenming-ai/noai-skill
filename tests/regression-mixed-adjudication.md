# 混合裁决回归案例

> 状态：离线行为规格，尚未执行独立模型评测。

## 目的

验证 noai 能在同一段文字中逐句裁决：改掉对象、动作或状态不匹配以及抽象包装，同时保护准确比喻与经验来源。不允许因为一个版本整体更自然，就把它的每处改动都当成正例。

## 输入片段

> 在团队里，写作 Agent 负责把想法变成最终文章。
>
> 稿子已经交了出来，只是比原来差。没飞。直接趴窝。
>
> 可 Prompt 只能告诉 AI 想要什么，不能替老师确认下一份课件有没有守住。
>
> 感觉能报警，不能破案。
>
> 我实际打磨下来发现，最累的，是上一次已经改对的东西，下一次还得重新操心。

## 预期裁决

1. “把想法变成最终文章”：必须改。当上下文只需交代职责时，收紧为“写文章”。
2. “直接趴窝”：必须改。结果已产出，只是质量下降，不能写成停止运行。
3. “下一份课件有没有守住”：必须改。课件是待检查的结果，不是“守住”要求的行动者，原句也没有给“守住”接上明确对象。应改为检查课件是否符合这些要求。
4. “感觉能报警，不能破案”：必须留。它准确压缩了“察觉异常≠拿出证据”，改成说明句只会变平。
5. “我实际打磨下来发现”：必须保留经验归属。若指代含混，可以说明实际打磨的对象；不得删掉经验来源，把亲历判断改成普遍断言。

## 失败条件

- 因为一句更直白或更短，就判定必须改。
- 把“守住”本身当成禁用词，不检查主体、动作对象和事件状态。
- 把所有比喻当成修辞过度，或把所有“我发现”当成铺垫。
- 只给整段或整个版本一个统一结论，没有逐句区分必须改与必须留。
- 为了保留经验来源，反过来禁止任何第一人称精简。
