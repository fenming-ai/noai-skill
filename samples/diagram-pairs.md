# 视觉媒介曲子库

> 以下为教学示例，不是实测或可直接套用的补写。具体技术、数字、日期、经历、代码行为和风险须有当前材料支持；缺少依据时只保留判断方向，不新增事实、不删必要信息、不改变程序语义。

> 架构图/流程图/可视化 的 AI 味 → 人味 对比对。
> 每首曲子 = AI 默认输出 + 人味改写 + WHY + 记住什么。
> 按媒介分文件，不按场景分——"文章"和"技术文档"可能共享表达问题，归文字媒介。

---

### 曲子 1：[有具体] 节点命名

AI 味：
```
[智能编排引擎] → [数据中枢] → [业务网关] → [智能决策层]
```

人味：
```
[K8s Scheduler] → [PostgreSQL] → [Nginx] → [规则引擎 v2]
```

WHY：
"智能编排引擎""数据中枢"是统计上最像"专业"的命名——AI 倾向选抽象功能名，因为它不知道具体用的是什么。人叫具体组件名（K8s Scheduler/PostgreSQL），因为人是看着真实系统画的。

记住什么：
节点叫具体组件名，不叫抽象功能名。"智能""引擎""中枢""枢纽"= AI 味。

---

### 曲子 2：[有取舍] 布局密度

AI 味：
```
所有服务都画上，12 个节点等大等距，全连线，颜色统一蓝色方块
```

人味：
```
只画关键路径 4 个节点（加粗放大），次要服务省略或缩小，关键路径粗线，次要细线
```

WHY：
AI 默认"面面俱到"——每个服务都画上，等权等距，因为统计上最安全的做法是"不遗漏"。人有取舍，知道关键路径是什么，次要的砍掉或缩小。

记住什么：
架构图不是全景图。砍掉一半元素，剩下的有轻重吗？有 = 人味。

---

### 曲子 3：[有节奏] 视觉留白

AI 味：
```
每个空都填满，无留白，每个节点都加说明文字，所有连线都标协议
```

人味：
```
核心节点放大有留白，次要节点缩小，只标关键路径的协议，其他不标
```

WHY：
"每个空都填满"是统计最可能的布局——AI 不知道该删什么就全填上。人有节奏感，知道密集和留白的对比让读者聚焦关键信息。

记住什么：
去掉装饰，信息还在吗？在 = 装饰是多余的。留白 = 有人在做选择。

---

### 曲子 4：[有判断] 风险标注

AI 味：
```
所有连线等粗，所有节点等大，没有"关键路径"和"可替代部分"的标注
```

人味：
```
关键路径标红加粗，单点故障标⚠️，可替代部分标灰虚线，写"这里挂了全盘崩"
```

WHY：
"等权等距"是统计最安全的——不标注 = 不做判断 = 不会错。人有好恶，会标"这里最危险""这个能替换""这个挂了全盘崩"。

记住什么：
架构图要有立场——标关键路径、标风险、标取舍。等权 = 没有判断 = AI 味。

---

### 曲子 5：[有温度] 人工痕迹

AI 味：
```
完美对称的布局，Mermaid 自动生成的默认样式，渐变背景，所有节点圆角统一
```

人味：
```
手绘风格的箭头标注，旁边写"2024-03 这里临时加的，等迁移完删"，关键决策点有标注理由
```

WHY：
完美对称 + 自动样式 = AI 味。真实架构图有迁移痕迹、临时方案标注、决策理由。人画图时有时间线和判断，不是一次性生成的"完美布局"。

记住什么：
完美 = 算法特征。人工痕迹（日期标注/临时方案/决策理由）= 人味。
